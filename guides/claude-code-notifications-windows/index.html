Get a Windows notification when Claude Code is waiting for you

Claude asks for permission, you are in another window, and nothing happens for twenty minutes. Three ways to make Windows tell you – from a simple beep to a real toast.

Updated 20 October 2026 · 5 min read

The idea: Claude Code hooks

Claude Code can run a command of your choice at certain moments. Two of these hooks matter here:

  • Notification – Claude needs you: a permission request, or it has been idle waiting for input.
  • Stop – Claude has finished its answer.

Hooks live in %USERPROFILE%\.claude\settings.json (for all projects) or in .claude\settings.json inside one project. If the file already exists, merge the "hooks" part into it instead of replacing the file.

1. The quick one: a beep

No installation needed. Windows PowerShell can play a tone:

{
  "hooks": {
    "Notification": [
      { "hooks": [ { "type": "command", "command": "powershell -NoProfile -Command \"[console]::beep(880,250)\"" } ] }
    ]
  }
}

Restart your Claude sessions so they pick up the new settings. Next time Claude asks for permission, you will hear it.

2. A real toast notification

A beep is easy to miss with headphones on. A toast shows up in the corner and stays in the notification center. The free PowerShell module BurntToast makes this a one-liner. Install it once:

Install-Module BurntToast -Scope CurrentUser

Then use it in the hook:

{
  "hooks": {
    "Notification": [
      { "hooks": [ { "type": "command", "command": "powershell -NoProfile -Command \"New-BurntToastNotification -Text 'Claude Code', 'Claude is waiting for you'\"" } ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command", "command": "powershell -NoProfile -Command \"New-BurntToastNotification -Text 'Claude Code', 'Done'\"" } ] }
    ]
  }
}

If nothing appears, check that Focus Assist / Do not disturb is off and that PowerShell is allowed to show notifications in Settings → System → Notifications.

3. Which session is it?

With one session, a toast is enough. With three, the next question is which one is waiting. The hook receives details as JSON on standard input, including the working directory (cwd), so you can put the project name into the toast. Save this as %USERPROFILE%\.claude\notify.ps1:

$data = [Console]::In.ReadToEnd() | ConvertFrom-Json
$project = Split-Path $data.cwd -Leaf
New-BurntToastNotification -Text "Claude Code - $project", $data.message

and point the hook at it:

"command": "powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/YOU/.claude/notify.ps1"

Replace YOU with your Windows user name. Forward slashes and the escaped quotes in these examples work whether the hook runs through cmd or Git Bash.

4. Away from the PC?

Toasts only help when you are at the desk. For a phone notification, people usually point the hook at a push service such as ntfy or Pushover with a small curl call. That works, but you still have to walk back to the PC to actually answer the prompt. To answer from the phone itself, see how to approve Claude Code permissions from your phone.

5. Or let a desktop do it: VibeDesk

Full disclosure: this site belongs to VibeDesk, a free and open-source app that does all of the above without editing JSON. It runs the real Claude Code CLI and adds:

  • A status dot per session – yellow means waiting for you, so you see which session at a glance.
  • Permission requests as cards with Allow, Always and Deny – answered in one click.
  • Your phone as a remote: it buzzes and you can approve from there, paired with a 6-digit code from your screen – on Wi-Fi or mobile data.

Checklist

  • A Notification hook in %USERPROFILE%\.claude\settings.json.
  • Beep for a start, BurntToast for a real toast.
  • Project name in the toast once you run more than one session.
  • Restart sessions after changing settings.
